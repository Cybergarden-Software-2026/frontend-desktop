# UnderCtrl Desktop

Рабочее место координатора инцидентов для Windows и macOS. Клиент на Electron открывает очередь, журнал и уведомления через `https://desktop.cybergarden.sosmooth.ru/api/v1`.

## Запуск клиента

При установленных Node.js 24 LTS и pnpm 11.25.0 выполните

```sh
git clone https://github.com/Cybergarden-Software-2026/frontend-desktop.git
cd frontend-desktop
pnpm install --frozen-lockfile
pnpm dev
```

При первом запуске войдите с учётной записью координатора или личным ключом. После входа откроется очередь. Если в профиле уже сохранён другой сервер, в настройках подключения укажите `https://desktop.cybergarden.sosmooth.ru` без пути и нажмите **Подключиться**.

### Работа с локальным бэкендом

Для разработки с отдельной базой запустите Rust API из репозитория `backend`. Понадобится Docker Desktop с Docker Compose.

```sh
git clone https://github.com/Cybergarden-Software-2026/backend.git
cd backend
cp .env.example .env
```

В PowerShell используйте `Copy-Item .env.example .env`. Если `.env` уже существует, используйте его. В новом файле задайте пароль PostgreSQL в `POSTGRES_PASSWORD` и соответствующий пароль в `DATABASE_URL`. При использовании специальных символов в URL закодируйте их. Контейнеры читают выгрузку из `backend/data/character_problems.json`.

```sh
docker compose up -d --build
docker compose ps
```

Откройте `http://127.0.0.1:8080/health/ready`. После миграции поле `database` должно быть `true`. Дождитесь первого импорта на `http://127.0.0.1:8080/api/v1/snapshot?view=web` — в массиве `items` появятся записи выгрузки. Состояние импортёра можно проверить командой `docker compose logs --tail 50 importer`. Запуск на PostgreSQL без Docker описан в [README бэкенда](https://github.com/Cybergarden-Software-2026/backend#readme).

В настройках подключения укажите `http://127.0.0.1:8080`. Режим входа определяется настройками выбранного бэкенда.

## Данные и действия

Все рабочие маршруты используют префикс `/api/v1`.

| Сценарий | HTTP / SSE |
| --- | --- |
| Вход, проверка и завершение сеанса | `POST`, `GET` и `DELETE /auth/coordinator/session` |
| Снимок и обновления | `GET /snapshot?view=web`, `GET /events/stream?view=web` с событиями `snapshot` |
| Очередь и карточка | `GET /incidents` с параметрами веб-очереди, `GET /incidents/{key}?view=web`, `GET /incidents/{key}/events`, `GET /incidents/{key}/analysis` |
| Команды и назначение | `GET /teams`, `POST /incidents/{sysId}/assignment` с `team` и `expectedRevision` |
| Группы сбоев | `GET /problems/clusters`, `PATCH /problems/clusters` с `action`, идентификаторами и `expectedRevision` |
| Журнал и уведомления | `GET /events` с курсорами, `GET /notifications`, `PUT /notifications/{id}/read` |
| Отчёт смены | `GET /statistics/shift?from=…&to=…` с границами в ISO 8601 |

Импортёр отслеживает исходную выгрузку. Появление записи, смена статуса, команды, срока или приоритета обновляют интерфейс. В источнике `priorityId = 4` соответствует критическому `P1`. Инцидент может одновременно войти в несколько групп. Сервер формирует уведомления при повышении до критического уровня, передаче координаторам и решении критического инцидента. Помощник показывает факты и рекомендации по правилам из действующего `/analysis`.

Во время работы приложение держит последний успешный снимок в памяти. Для серверов с открытым доступом оно также сохраняет снимок в локальном хранилище отдельно для каждого адреса. При обрыве соединения клиент показывает время обновления снимка, предлагает повторить запрос и автоматически восстанавливает подписку. Для записи требуется соединение. После `409` актуальная ревизия нужна для явного повторного назначения. Групповое назначение выполняется последовательно и показывает частичные результаты.

Для перехода в рабочую ITSM заполните `ITSM_BASE_URL` и `ITSM_URL_TEMPLATE` в `.env` бэкенда и примените изменения через `docker compose up -d`. Импорт новых инцидентов и внешние изменения статусов проходят через источник ITSM и импортёр. Подробности контрактов приведены в [API.md](https://github.com/Cybergarden-Software-2026/backend/blob/HEAD/API.md).

## Демонстрация живого обновления

На демонстрационной копии выгрузки откройте очередь и найдите `INC000021938167`. Из каталога `backend` выполните следующие команды по очереди, наблюдая приложение между шагами. Скрипту нужен Python 3.11+.

```sh
python3 tools/demo.py step1
python3 tools/demo.py step2
python3 tools/demo.py step3
python3 tools/demo.py step4
python3 tools/demo.py reset
```

Первый шаг повышает приоритет и передаёт запись координаторам. Второй меняет дедлайн, третий переводит инцидент в исследование, четвёртый передаёт его инженерам. Последняя команда возвращает исходную демонстрационную выгрузку. В Windows с Python Launcher используйте `py -3` вместо `python3`.

## Сборка и проверки

Используйте Node.js 24 LTS и pnpm 11.25.0. Если pnpm отсутствует, установите его командой `npm install -g pnpm@11.25.0`. Первая установка и упаковка требуют доступа к реестру npm и официальным дистрибутивам Electron. В дальнейшем интерфейс, шрифты, иконки и генераторы отчётов загружаются из приложения.

| Команда в корне репозитория | Результат |
| --- | --- |
| `pnpm check` | Строгая проверка TypeScript |
| `pnpm lint` | ESLint для интерфейса, процесса Electron и скриптов |
| `pnpm build` | Production-интерфейс в `dist/` |
| `pnpm start` | Нативное окно с последней production-сборкой |
| `pnpm package:win` | `release/UnderCtrl-1.0.0-win-x64.zip` для Windows x64 |
| `pnpm package:mac` | `release/UnderCtrl-1.0.0-mac-universal.zip` для Intel и Apple Silicon, сборка выполняется на macOS |

Для демонстрации распакуйте архив целиком и запустите `UnderCtrl.exe` или `UnderCtrl.app`. На демонстрационной машине нужен доступ к бэкенду. Node.js и pnpm требуются только для разработки и сборки. Это локальные сборки без издательского сертификата Windows и нотарификации Apple.

В разработке Vite обслуживает интерфейс на `127.0.0.1:5173`. Само окно использует `underctrl://desktop/` в обоих режимах. Основной процесс Electron передаёт запросы `/api/v1/…` и поток SSE выбранному серверу. `UNDERCTRL_API_ORIGIN` позволяет задать другой исходный адрес, например `http://127.0.0.1:8080`. Адрес, выбранный пользователем в настройках, хранится в файле `connection.json` профиля Electron и имеет приоритет.

### Проверка готовых сборок

На macOS с Apple Silicon проверены запуск упакованного `UnderCtrl.app`, соединение с Rust API и PostgreSQL, копирование номера, смена адреса, открытие сохранённой очереди при обрыве связи и повторное подключение. На изолированной выгрузке из 44 записей проверены SSE, поиск и фильтры, назначение команды, анализ, чтение уведомлений, изменение и восстановление группы, генерация PDF и XLSX. Для Windows x64 собран ZIP и проверена целостность архива. Запуск на Windows в этой среде проверить не удалось.
